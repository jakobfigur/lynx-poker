## 1. What will be built, in order

### 1.1 Define leaf values (1 day)
Leaf = end of flop betting round (start of turn) or end of turn betting round (start of river), both still with chips.
Input to the value network: public state (board as card embedding or 52-bit, pot, effective stack, who acts first) plus **both ranges** (each 1326 weights, normalized). Output: value per combination for player 0
(1326 values, in pot units); player 1 follows from zero-sum. This is the ReBeL/DeepStack form ("public
belief state → counterfactual values"). File: `ai/valuenet.py` (network definition + loading), `ai/valuedata.py`
(generation).

**Correction 29.10 evening (after the first measurement):** an exact turn solution with all river cards costs 10–40 s,
an exact river solution 0.4–1 s. 500,000 exact turn situations would be hundreds of core days. Therefore, **order as in
DeepStack**: (1) exact river data → river network, (2) leaf nodes in the search, (3) turn data with river network at
leaves (then ≈ 1 s per situation) → turn network, (4) flop data with turn network → flop network. Each stage measurable separately. First dataset: 300,000–500,000 river situations ≈ 70 core hours ≈ 2–3 h on two CPX51.
Built 29.10: `ai/valuedata.py` (situations, synthetic ranges, solving, .npz shards), CLI
`pc.cmd train valuedata river --n 1000 --workers 4`, tests `test_valuedata.py`. Trial run: 12 river situations,
0.95 s per situation under full load, zero-sum per situation < 0.001 pot.

### 1.2 Data generation (3–4 days building, then computation time)
- Drawing random situations: board (flop or turn), pot/stack ratio from the distribution of real hands
(from our tournament and cash formats), **ranges** mixed from two sources: (a) ranges generated by our own
search/`ranges.py` in played hands, (b) randomly distorted ranges (Dirichlet noise, subsets), so the network also evaluates ranges outside equilibrium (robustness against model errors).
- Each situation solved **exactly** with the existing CFR+ search (turn: all river cards; flop leaves: turn tree
with all river cards, 200–400 iterations) → target values per combination = counterfactual values at the root.
- Scope: 300,000–500,000 situations. Cost per situation on the laptop ≈ 2–6 s (kernel parallel), on 32
Hetzner cores ≈ 0.2 s → 20–30 hours on two CPX51 ≈ €6–8.
- Format: `data/valuenet/<satz>.npz` (board IDs, state, ranges float16, target values float16), file size ≤ 2 GB each.
- Validation: 1% holdout, compare network vs. exact solution (mean absolute error in pot fractions; target < 1.5% of the pot).

### 1.3 Train value network (Kaggle, 1–2 days including waiting)
- Network: MLP with 3–4 layers of 1024 each (ReBeL scale), input ≈ 2,700 values, output 1326, Huber loss
in pot units, zero-sum constraint as side condition. ≈ 6–8 million parameters.
- Kaggle: T4/P100, 30 GPU hours per week, session ≤ 9–12 h → training in 2–3 sessions of 4–6 h with
checkpoints in private dataset. Script `kaggle/train_valuenet.py` (standalone, only numpy/torch).
- Result back to laptop: `data/valuenet/vnet-1.pt` (≈ 30 MB), runs on CPU in < 2 ms per leaf
(batching all leaves of a tree in one call).

### 1.4 Integration into the search (2–3 days)
- `husearch.py`: new node type `LEAF` at the end of flop or turn betting round; `_solve` gets per leaf the
value vectors from the network (computed once before iterations; the ranges at the leaf change with
iterations → re-evaluate every 10 iterations, as in ReBeL).
- Then the flop tree becomes small (no more cards drawn) and the turn tree exact and fast:
Target < 0.5 s per live decision at 100+ iterations.
- Safety: never let the opponent range at the leaf drop below a small floor (protection against model errors),
mixing with the previous pure play as fallback if the network does not know a situation.

### 1.5 Measurements (ongoing)
Order of metrics per version: (1) hu480 paired against network and the previous search, (2) Slumbot
cleaned 5,000–10,000 hands, (3) GTO Wizard 5,000 hands AIVAT. Live standard changes only upon significant
win on (1) and no worse on (2).

### 1.6 Afterwards: Distillation into the network (Expert Iteration, Milestone 4)
The search decisions become training targets for lynx-5 (Behavior Cloning + PPO fine-tuning), so strength also arrives 6-handed and in the rail without search. This includes opponent model exploitation (H6) in the search.

## 3. Risks and countermeasures
- Network mis-evaluates ranges outside training distribution → noise ranges in data (1.2 b), floor
for opponent range, fallback to pure play.
- Search wins heads-up, but nothing changes 6-handed → Milestone 4 (distillation), parallel ICM training.
- Kaggle quota insufficient → second account not allowed; instead training on Hetzner server (CPU,
2–3 days, ≈ €10) or RunPod Community 4090 ($0.34/h, ≈ $5).
- Memory watchdog/screensaver on laptop → long runs only detached (Start-Process) or on the server.

## 3a. Addendum from competitor analysis (29.10., `GTO_COMPETITOR_ANALYSIS.md`)
- **Training distribution:** ReBeL shows that a value network trained on purely random ranges learns nothing useful.
Therefore at least 50% of situations from real search play (leaf ranges logged during benchmark/selfplay), 50% structured-random. Compose both batches accordingly, measure learning curve per source.
- **Blueprint warmstart** of the search from lynx-4 (instead of uniform start strategy) before expanding iterations; DecisionHoldem needs 6,000–10,000 iterations without, ReBeL few hundred with warmstart.
- **Search space** after river network on `wide` plus third raise size.
- **Metrics:** GTO Wizard AIVAT is main metric; Slumbot only as preliminary (> 0 secured is enough).
